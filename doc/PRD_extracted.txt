1. Executive Summary
RoboAIAPaths is a full-stack Learning Management System built for a robotics and AI education brand. The platform serves three distinct roles — Admin, Instructor, and Student — with mobile-number OTP authentication, role-based content delivery, PayU payment integration, watermarked content protection, AI-powered learning tools, live sessions with chat, and an intelligent notes workspace.

The system is designed to be launched as a web application (Next.js 14) with companion Android (Kotlin/XML) and iOS apps, backed by a Node.js REST API, PostgreSQL, Redis, and Cloudflare CDN for HLS video delivery.


2. Goals & Non-Goals
2.1 Goals
Deliver a secure, role-based LMS for robotics kits, AI tutorials, and future IT/development courses.
Support three user roles with distinct content access rules enforced server-side.
Implement OTP login (SMSMeta), PayU checkout, and webhook-based access grants.
Protect all paid content via HLS signed URLs (video) and server-side PDF watermarking.
Provide AI features: video summary, topic Q&A, notes AI, and mindmap generation.
Support live instructor sessions with invite-link or open-broadcast modes and live AI chat summary.
Launch device-binding system: one active device per user, admin approval required for additional devices.
Ship web (Next.js), Android (Kotlin/XML), and iOS (React Native) clients from a single backend.

2.2 Non-Goals (V1)
Native iOS build — PWA + React Native wrapper is acceptable for V1.
Multi-language support — English/Hindi only for V1.
Peer-to-peer discussion forums — single-instructor live chat is in scope; async forums are V2.
Offline video download — PDF offline is V1; video offline is V2.

7. Backend Build Guide — Step by Step
Build and test the entire backend first before touching the frontend. Every endpoint should be tested in Postman before proceeding to the next module.

Phase 1 — Project Setup
mkdir roboaiapaths-api && cd roboaiapaths-api && npm init -y
npm install fastify @fastify/jwt @fastify/cookie @fastify/multipart @fastify/cors dotenv pg redis ioredis bull bullmq zod uuid axios pdf-lib sharp
npm install -D typescript ts-node nodemon @types/node jest supertest
Create folder structure: /src/{routes,services,middleware,db,jobs,utils}
Set up .env: DATABASE_URL, REDIS_URL, JWT_SECRET, SMSMETA_KEY, PAYU_KEY, PAYU_SALT, R2_BUCKET, R2_ACCOUNT_ID, R2_ACCESS_KEY, R2_SECRET_KEY, AI_API_KEY
Set up Prisma: npx prisma init → define all schemas above → npx prisma migrate dev --name init
Test DB connection in Postman: GET /healthcheck returns { db: 'ok', redis: 'ok' }

Phase 2 — Authentication Module
Create SMSMeta service: POST to SMSMeta API with mobile, store OTP + TTL=5min in Redis as otp:{mobile}
POST /auth/otp/request: validate mobile regex → call SMSMeta service → 200 OK
POST /auth/otp/verify: get otp from Redis → compare → if match: create/fetch user → sign JWT → set refresh cookie
Middleware: authenticate() — verify JWT, attach req.user
Middleware: authorize(roles[]) — check req.user.role
Postman tests: request OTP → verify OTP → get JWT → call GET /auth/me with Bearer → expect user object
Test OTP retry limit: call verify 5 times with wrong OTP → expect 429 on 6th

Phase 3 — Device Binding Module
On OTP verify: extract device_id from request body → check devices table → if no record: insert as active → if mismatch: return 403 with DEVICE_MISMATCH error
POST /devices/request: insert devices row with status=pending
Admin endpoints: GET /admin/devices/requests → PUT approve → PUT reject → POST forcelogout (Redis blacklist)
Postman: login with device_id_A → login again with device_id_B → expect 403 → POST /devices/request → approve as admin → login again with device_id_B → expect 200

Phase 4 — Content Management Module
Set up Cloudflare R2 client using @aws-sdk/client-s3 (R2 is S3-compatible)
POST /courses: create course record with admin JWT
POST /courses/:id/videos: multipart upload → stream to R2 at key courses/{courseId}/videos/{uuid}.mp4 → queue FFmpeg HLS transcode job in BullMQ
BullMQ worker: transcode MP4 to HLS (m3u8 + ts segments) → upload segments to R2 → update lesson.r2_key to .m3u8 path
POST /courses/:id/pdfs: upload PDF to R2 at key courses/{courseId}/pdfs/{uuid}.pdf
GET /courses/:id/stream/:lessonId: check user_course_access → generate CloudFront signed URL (1hr TTL) → return URL
GET /courses/:id/pdf/:lessonId: check user_course_access → fetch PDF from R2 → watermark with pdf-lib (overlay user display name + user ID + timestamp diagonal across each page) → stream to client
Postman: upload course → upload video → poll job status → verify signed URL works → verify unsigned URL returns 403

Phase 5 — Payments Module
POST /orders/initiate: create pending order in DB → compute PayU hash (SHA512 of key|txnid|amount|productinfo|firstname|email|||||||||||salt) → return PayU params to frontend
POST /webhooks/payu: verify incoming HMAC from PayU → if valid and status=success: update order to success → insert user_course_access → return 200
GET /orders: list user orders with course names and bundle types
Postman: initiate order → manually trigger test webhook with test credentials → verify access row created → call stream endpoint → should now return signed URL
Test failure path: webhook with status=failure → order stays pending → stream endpoint returns 403

Phase 6 — Live Sessions Module
Install LiveKit SDK: npm install livekit-server-sdk
Create LiveKit Cloud project (or self-host); store LIVEKIT_API_KEY and LIVEKIT_API_SECRET in .env
POST /sessions: create session record in DB
POST /sessions/:id/start: create LiveKit room via SDK → return instructor join token
GET /sessions/:id: generate viewer join token for authenticated user → return token + LiveKit URL
WebSocket /sessions/:id/chat: use Fastify websocket plugin; store messages in DB; broadcast to all connected clients
POST /sessions/:id/end: mark session ended → queue AI summary job (pass all chat messages + transcript if available)
Postman: create session → start → get viewer token → verify token structure → end session → poll summary job

Phase 7 — AI Module
Set up AI service using Anthropic Claude API (or OpenAI); store key in .env
For video transcripts: integrate AssemblyAI or Whisper on the HLS recording; store transcript in DB after session ends
POST /ai/summarise/:lessonId: fetch transcript → send to LLM with prompt 'Summarise this lesson into key chapters and bullet points' → store in ai_jobs → return jobId
GET /ai/jobs/:id: poll job status and result
POST /ai/ask: fetch course transcript/notes as context → RAG query to LLM → return answer with source references
POST /ai/polish-notes: send raw notes text to LLM with prompt 'Format these notes into beautiful structured markdown with headings, bullets, and emphasis' → return formatted text
POST /ai/mindmap: send topic/notes to LLM requesting JSON mindmap tree { root, children: [{label, children}] } → validate and return JSON
Postman: test each AI endpoint with sample text/lesson IDs; verify JSON structure for mindmap endpoint

Phase 8 — Notes Module
GET/POST/PUT/DELETE /notes: standard CRUD; content stored as Tiptap JSON in JSONB column
GET /notes/:id/export: for PDF export, use pdf-lib to render note content; for MD export, convert Tiptap JSON to markdown
Postman: create note → update → export as PDF → download and verify content

10. Scalability & Architecture Notes

10.1 Video Delivery
All videos transcoded to multi-bitrate HLS (360p/720p/1080p) for adaptive streaming.
Segments stored in Cloudflare R2; served via CloudFront with signed cookies (not per-URL) for playlist + all segments.
AES-128 HLS encryption: key served from API (requires valid JWT), not from CDN.

10.2 API Scaling
Stateless Fastify API pods; scale horizontally via Kubernetes HPA.
All session state in Redis; no in-memory state on API pods.
BullMQ workers run as separate pods; scale independently of API.

10.3 Database
PostgreSQL with read replicas for course listing and analytics queries.
Indexes on: users.mobile, orders.user_id, user_course_access.(user_id, course_id), devices.user_id.
Soft deletes on courses and users (deleted_at column) to preserve order history.

10.4 Security
All secrets in environment variables, never in code.
JWT secret rotated every 90 days; old tokens blacklisted via Redis.
PayU HMAC verification on every webhook; reject if signature mismatch.
PDF watermark includes user ID, device ID, and timestamp to trace leaks.
FLAG_SECURE on all video screens in Android; disables screenshot API.
Rate limiting: 5 OTP requests per mobile per hour; 100 API requests per minute per IP.

10.5 Release Strategy
Phase 1 (4 weeks): Auth + Courses + Payments + Device Binding — core LMS working.
Phase 2 (3 weeks): Live Sessions + Notes App + Android app.
Phase 3 (3 weeks): AI features (summary, Q&A, mindmap, notes polish).
Phase 4 (2 weeks): iOS app, analytics dashboard, coupon system, export features.
